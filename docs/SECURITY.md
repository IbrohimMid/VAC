# Security Policy

## Supported Versions

Currently, only the latest release of this project is supported with security updates. We encourage users to upgrade to the latest version to ensure they have the most recent security patches.

| Version | Supported          |
| ------- | ------------------ |
| Latest  | :white_check_mark: |
| Older   | :x:                |

## Reporting a Vulnerability

We take the security of this project seriously. If you discover a security vulnerability, please let us know right away.

### How to Report

Please do **not** report security vulnerabilities through public GitHub issues. 

Instead, please report them by emailing the security team or the maintainers directly at [security@example.com](mailto:security@example.com) (or the designated security contact for this project).

When reporting a vulnerability, please include as much information as possible:
- A description of the vulnerability and its potential impact.
- Steps to reproduce the vulnerability.
- Any relevant logs, screenshots, or code snippets.
- Potential mitigation or remediation if known.

### Response Timeline

1. **Acknowledgment**: We will acknowledge receipt of your vulnerability report within 48 hours.
2. **Triage**: We will investigate the issue and determine its validity and severity within 5 business days.
3. **Remediation**: If the vulnerability is confirmed, we will work on a patch. The timeline for remediation depends on the severity and complexity of the issue.
4. **Disclosure**: Once the vulnerability is patched and released, we will publish a security advisory and acknowledge your contribution (if you wish to be credited).

### Coordinated Disclosure

We ask that you give us a reasonable amount of time to fix the vulnerability before making any information public. We will work with you to coordinate a public disclosure timeline.
