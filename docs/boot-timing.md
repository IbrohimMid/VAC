# Boot Timing Breakdown

Generated by `cargo nextest run -p vac_tui_runtime --test first_paint_harness`.
All timings in microseconds on the machine running the test.

## Sample run (2026-04-23)

| Step | µs |
|---|---|
| `VacConfig::load_with_fallback` | ~3,000 |
| `AppState::new` | ~2,000 |
| `VacConfig::minimal` | ~500 |
| **total** | **~5,500** |

Budget: synchronous pre-paint work under 50,000µs (50ms). If total
exceeds this, the harness test fails.

## What the harness measures

- `VacConfig::load_with_fallback(&project_root)` — reads
  `.vac/config.toml` if present, else defaults. Sync disk I/O +
  `toml::from_str`.
- `AppState::new(opts)` — constructs 20+ sub-struct defaults. All
  in-memory; no disk I/O.
- `VacConfig::minimal()` — stripped-down config used by `vac eval
  --minimal`. Shows the floor cost of constructor.

## What the harness does NOT measure

- Kitty graphics probe (blocking 200ms worst case, TTY-gated). Not
  covered by tests because it needs an interactive terminal.
- `load_session_snapshot` — deferred past first frame (O1), so
  does not block first paint anymore.
- MCP probe, theme watcher, keybindings watcher — all spawned
  background tasks, not on critical path.

## How to re-run

```bash
cargo nextest run -p vac_tui_runtime --test first_paint_harness
```

The harness overwrites this file on each run with the latest timings.
